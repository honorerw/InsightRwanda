# Phase 21 — Judge demonstration script

Suggested duration: 5–7 minutes. Use the Overview page's **Judge walkthrough** selector to follow these eight steps. Demonstrate the application’s actual metadata-driven behavior. Do not load source records or present test fixtures as research findings.

1. **Problem and intended value.** Introduce the Financial Inclusion & Poverty Reduction research purpose; explain that no verified estimate is currently available.
2. **Architecture and navigation.** Use the existing sidebar pages and explain the metadata/evidence-to-readiness workflow.
3. **Provenance and authorization.** Show source verification and explain why public discovery or a local file does not grant permission.
4. **Indicator and methodology.** Show FI-ACCESS-001 as a candidate; no estimate was calculated because release, mapping, authorization, and methodological prerequisites remain unresolved.
5. **Available visual findings.** Explain that only eligible aggregates can be charted. There are none currently; synthetic tests are not shown as findings.
6. **Geographic and statistical safeguards.** Show missing verified boundaries/joins, unsupported design needs, and separate disclosure review.
7. **Reproducibility and integrity.** Point reviewers to Phase 14–20 implementation/tests. A checksum supports content consistency but not authorization or authenticity.
8. **Limitations and next evidence.** Name the exact-release authorization, source documentation, mappings, approved specification/survey design, quality validation, and separate disclosure/publication review needed. Geographic publication additionally needs verified boundaries, compatible keys/version, safe joins, and map-specific approval.
